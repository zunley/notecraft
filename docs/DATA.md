# 数据在哪、怎么同步

一页说清三件事：**客户端存了什么、服务端存了什么、同步怎么走**。

## 总览

```
   设备上（明文，文件即真相）              服务端（零知识，只有密文）
┌─────────────────────────┐           ┌──────────────────────────────┐
│ 笔记 .md                 │           │ /notes/<uid>/  笔记密文仓库    │
│  Web → 浏览器 OPFS       │  同步出口  │   ├ meta.json  清单 + rev     │
│  桌面 → 你选的真实文件夹   │ ───────► │   └ files/<路径密文>          │
│                         │  (加密后)  │                              │
│ localStorage / IndexedDB│ ◄─────── │ /data/       账号（无笔记内容） │
│  token、同步基线、AI 会话  │  (解密后)  │                              │
└─────────────────────────┘           └──────────────────────────────┘
```

一句话：**本地永远是明文，服务端永远是密文；加密只发生在同步出口这一步。**

---

## 一、客户端数据

### 1. 笔记本本体 = 一堆 `.md` 文件

| 端 | 放在哪 | 说明 |
|----|--------|------|
| Web | 浏览器 **OPFS**（站点私有存储） | 用户看不到、不占下载目录；清站点数据会丢 |
| Windows / macOS / Linux / iOS（Tauri） | **你选的那个真实文件夹** | 首次启动弹窗选择，路径记在 `notecraft.noteDir`；可用 VS Code 等任意编辑器打开 |

- 目录结构即笔记本结构；删除先进 **`.trash/`**（回收站，随同步走），回收站里再删才是真删；
- AI 助手的读写工具打的就是这批文件，没有第二套存储；
- 编辑中的草稿只在编辑器内存里，⌘S / 切换文件时落盘，不单独存。

### 2. 浏览器/应用本地的杂项（不进同步）

| 位置 | 键 | 内容 |
|------|----|------|
| localStorage | `notecraft.token` | 登录通行证（有效期 72h） |
| localStorage | `notecraft.username` | 当前用户名 |
| localStorage | `notecraft.noteDir` | 桌面端选定的笔记目录 |
| localStorage | `notecraft.sync.baseline.<路径>` | 每个文件上次同步的哈希基线（冲突判断用） |
| localStorage | `notecraft.serverUrl` | 手动指定服务端地址（一般为空，同源） |
| IndexedDB | `notecraft` / `sessions` | AI 对话历史，**仅本机**，服务端零留存 |
| 内存 | MK 主密钥 | 加密密钥，**刷新/重启即失**，需重新登录或用恢复密钥解锁 |
| 内存 | 编辑器草稿 | 未落盘的输入 |

## 二、服务端数据

compose 把两个目录挂出来：`./notes → /notes`、`./data → /data`。

### 1. `/data` —— 账号与密钥，**没有笔记**

```
/data/
├── token_secret                 # 签发 token 的密钥（env NOTE_MD_TOKEN_SECRET 优先；丢失=全部登录失效）
└── users/
    ├── <uid>.json               # 一个账号一个文件
    └── by-username/<用户名>      # 用户名 → uid 的唯一索引（登录用）
```

`<uid>.json` 里只有四样东西：

| 字段 | 是什么 |
|------|--------|
| `uid` | 随机 16 字节十六进制，注册时生成、终身不变（`/notes/<uid>/` 用它分目录） |
| `username` | 用户名（仅作登录句柄，不进任何路径） |
| `login_verifier` | `sha256(L)`——**哈希**，L 是客户端用 Argon2id 从口令派生的高熵凭证，口令本身从没上传 |
| `protected_key` | 用 KEK 包好的密文信封，服务端只负责存与还，**打不开** |

> 拖库能拿到的只有：用户名、一个哈希、一个打不开的信封——**读不到任何笔记**。
> `/data` 必须备份（丢了账号就没了），但里面没有笔记内容。

### 2. `/notes` —— 笔记密文仓库

```
/notes/<uid>/
├── meta.json                    # 清单：rev（该用户的同步计数器）+ 每个文件的密文 hash/mtime/size
└── files/<路径密文>              # 一段 base64url 密文 = 一篇笔记
```

- **路径也加密**（确定性加密：同一路径永远算出同一密文，服务端靠它定位文件）；
- 内容按 4KiB 对齐填充，掩蔽真实长度；`mtime` 按天舍入；
- 服务端对内容做的一切就是：存、还、比对 sha256——不理解任何明文语义。

### 3. 只在内存里的（重启即清零）

- AI 中继日配额计数（默认 200 次/天/用户）
- 注册/登录限速计数（默认 10 次/分/IP）

### 4. 默认限额

| 项 | 默认 | 变量 |
|----|------|------|
| 单文件密文上限 | 1 MiB | `NOTE_MD_FILE_MAX` |
| 每用户存储配额 | 1 GiB | `NOTE_MD_STORAGE_QUOTA` |
| AI 中继日配额 | 200 次/天/用户 | `NOTE_MD_RELAY_DAILY_QUOTA` |
| 登录有效期 | 72 小时 | `NOTE_MD_TOKEN_TTL` |
| 注册策略 | 开放 | `NOTE_MD_REGISTRATION` |

## 三、同步规则

### 什么时候同步
- 保存后防抖约 **2 秒**自动推；
- 切回前台 / 窗口聚焦 / `visibilitychange` 时对齐一次；
- 状态栏「**立即同步**」手动触发；
- **未登录或未解锁时静默跳过**——本地编辑照常，联网登录后自动补上。

### 怎么推、怎么拉
- **拉**：取服务端清单（`meta.json`）→ 解密路径 → 和本地逐个比对 → 变了的才下载 → 解密写回本地；
- **推**：本地改动加密后 `PUT`，带上「上次同步时的密文哈希」作为 `base_hash`。

### 乐观锁与冲突（核心）
```
PUT 时 base_hash ≠ 服务端当前 hash  →  409 conflict
    → 下载服务端版本作为新基线
    → 本地内容另存一份「名字 (冲突 20251106-1030).md」
    → 然后正常推送            ★ 不做自动合并，两边都保留
```

- 同步比对用的是**密文哈希**（`sha256(传输字节)`）；
- 本地判断「我改过没有」用的是**明文哈希**——两者都记在 `notecraft.sync.baseline.*` 里。

### 删除怎么传播
| 情况 | 动作 |
|------|------|
| 服务端删了、本地没改 | 本地文件移进 `.trash/`（不声不响丢文件的事不干） |
| 本地删了 | 向服务端发 DELETE，同样带 `base_hash`；409 就先取最新再删 |
| 回收站里的再删 | 真删（本地与服务端同步消失） |

### 其他约定
- `rev` 是**每个用户自己的**计数器，只有该用户自己的推送会推进它——它只是同步进度，不是版本号；
- 同步协议带 `protocol` 字段，服务端协议过新会提示升级客户端，不硬来；
- 冲突、超限（413 单文件超大 / 507 超配额）都会在状态栏给出提示，不静默丢数据。

## 四、备份什么

| 目录 | 内容 | 丢了会怎样 |
|------|------|-----------|
| `./data` | 账号表 + token 签名密钥 | **账号全部作废**（笔记还在，但登不进） |
| `./notes` | 全部笔记密文 | 笔记全丢 |

两个都要备。密文是端到端加密的，备份文件本身不含明文——但**没有口令/恢复密钥照样打不开**，恢复密钥请离线单独保存。
